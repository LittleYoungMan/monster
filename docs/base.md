# 2. 主要功能2

```gdscript
## 常量名称

## 变量名称

## 📐 总体技术要求

### 分辨率与显示

**开发基准**：
- 以1080p (1920×1080) 为基准进行开发
- 角色大小：96-128px
- 摄像机Zoom：建议设为2.0（让角色显示更大，不会太小）
- 窗口模式：可切换窗口/全屏
- 缩放模式：`canvas_items`（保证UI正确缩放）
- 宽高比：`expand`（自适应不同屏幕）

**project.godot配置**：
```ini
[display]
window/size/viewport_width=1920
window/size/viewport_height=1080
window/size/mode=0
window/stretch/mode="canvas_items"
window/stretch/aspect="expand"
```

**Camera2D配置**：
```gdscript
# 在Player场景的Camera2D节点
@onready var camera: Camera2D = $Camera2D
camera.zoom = Vector2(2.0, 2.0)  # 放大2倍，让角色不会太小

- 所有图片原始尺寸：256×256 PNG（支持任意缩放不失真）

### 数据导入规范

**CSV文件要求**：
- 编码：UTF-8 with BOM
- 分隔符：逗号
- 第一行：表头（字段名）
- 空值处理：数值字段用0，文本字段可为空
- 存放路径：`res://data/`

**数据加密**：
- 开发阶段：使用明文CSV（方便调试）
- 导出游戏后：Godot自动将资源打包进.pck文件（相当于加密）
- 额外保护：可使用Godot的Export加密功能
- 结论：不需要额外的加密代码

**Excel导出步骤**：
1. 在Excel中编辑数据
2. 文件 > 另存为
3. 选择"CSV UTF-8 (逗号分隔)(*.csv)"
4. 保存到项目的`data/`文件夹
5. 覆盖同名文件

**数据加载时机**：
- 游戏启动时自动加载（GameData._ready()）
- 热重载：重新运行游戏即可

## 📊 数据流转详解

### 1. 角色系统数据流

```
启动游戏
    ↓
GameData._ready()
    ↓
读取 data/characters.csv
    ↓
解析CSV → 存入 GameData.characters 字典
    ↓
玩家选择角色ID（如"hero_01"）
    ↓
Player.load_character_data(character_id)
    ↓
从 GameData.characters 获取角色原始数据
    ↓
Player.calculate_stats(level=1)
    ├─ 读取 base_属性（基础值）
    ├─ 读取 growth_属性（成长值）
    └─ 计算：当前值 = base + growth × (level - 1)
    ↓
存入 Player.current_stats（基础属性）
    ↓
初始化 Player.equipment_bonus = 0（装备加成）
初始化 Player.shop_bonus = 0（商店加成）
    ↓
最终属性 = 基础属性 + 装备加成 + 商店加成
```

**关键函数**：

```gdscript
# 获取最终属性（考虑所有加成）
func Player.get_final_stat(stat_name: String) -> float:
    return current_stats[stat_name] + equipment_bonus[stat_name] + shop_bonus[stat_name]
```

### 2. 武器系统数据流

```
商店生成武器 / 玩家装备初始武器
    ↓
创建武器实例数据（Dictionary）
    {
        "weapon_id": "wp_xxx",      # 武器模板ID
        "quality": "blue",           # 品质
        "attributes": [              # 工坊属性数组
            {"type": "crit_rate", "value": 5.0, "locked": false}
        ],
        "slot_index": -1             # 槽位（-1表示未装备）
    }
    ↓
Player.add_weapon(weapon_data)
    ↓
检查是否有空槽位（0-5）
    ↓
如果有空位：
    ├─ 存入 Player.weapon_slots[i] = weapon_data
    ├─ weapon_data["slot_index"] = i
    ├─ 在场景中实例化武器节点
    │   └─ 加载对应场景（melee_weapon.tscn / ranged_weapon.tscn）
    │   └─ 调用 weapon.initialize(weapon_data, player)
    │   └─ 添加到 Player/WeaponContainer 下
    └─ Player.recalculate_equipment_bonus()
        └─ 遍历所有weapon_slots的attributes
        └─ 累加到 equipment_bonus
    ↓
武器节点开始自动攻击
    ├─ 攻击计时器触发（冷却时间）
    ├─ 查找范围内敌人
    ├─ 调用 calculate_damage()
    │   ├─ 获取武器模板数据（从GameData）
    │   ├─ 获取玩家最终属性（get_final_stat）
    │   ├─ 应用伤害公式（见后文）
    │   └─ 返回最终伤害
    └─ 对敌人造成伤害
```

**伤害计算公式（完整版）**：
```
第一步：基础伤害计算
    base = weapon.base_damage

第二步：BonusClass加成
    bonus_dmg = player.get_final_stat("对应伤害类型") × weapon.damage_mult
    # 例如：BonusClass=M，则使用 melee_dmg
    # damage_mult 是继承系数（通常0.8-1.2）

第三步：全伤害加成
    all_dmg_mult = 1 + player.get_final_stat("all_dmg") / 100

第四步：品质加成
    quality_mult = {
        "white": 1.0,
        "blue": 1.15,
        "purple": 1.35,
        "gold": 1.6
    }

第五步：工坊属性中的直接伤害加成
    weapon_dmg_bonus = 累加weapon.attributes中type="damage"的value

第六步：计算最终伤害（不含暴击）
    final_dmg = (base + bonus_dmg) × all_dmg_mult × quality_mult + weapon_dmg_bonus

第七步：暴击判定（每把武器独立继承）
    weapon_crit_rate = player.get_final_stat("crit_rate") × weapon.crit_rate_inherit
    # crit_rate_inherit是武器的会心率继承百分比（0.0-1.0）
    
    if random() < weapon_crit_rate / 100:
        weapon_crit_dmg = player.get_final_stat("crit_dmg") × weapon.crit_dmg_inherit
        # crit_dmg_inherit是武器的会心伤害继承百分比（0.0-1.0）
        
        crit_mult = 1.5 + weapon_crit_dmg / 100
        final_dmg ×= crit_mult

注意：不同武器的crit_rate_inherit和crit_dmg_inherit可以不同

DPS计算（每秒伤害）：
    # 冷却计算：基础冷却 × 冷却系数 × (1 + 冷却继承 × 玩家冷却效率)
    actual_cooldown = weapon.base_cooldown × weapon.cooldown_mult × (1 + weapon.cdr_inherit × player.get_final_stat("cdr"))
    
    DPS = final_dmg / actual_cooldown
```

### 3. 商店系统数据流

```
游戏时间触发商店
    ├─ 前期（0-3分钟）：每30秒
    └─ 后期（3分钟后）：每60秒
    ↓
GameManager 发出信号 shop_door_triggered
    ↓
在玩家附近生成商店门（碰撞体）
    ├─ 前期（0-3分钟）：生成在玩家身边（距离50-100px）
    └─ 后期（3分钟后）：随机远近（距离100-500px）
    ↓
玩家进入碰撞体
    ↓
ShopManager.generate_shop_offers()
    ├─ 生成4张卡
    │   ├─ 武器卡（前期概率高，后期概率低）
    │   │   ├─ 前期（0-5分钟）：70%武器，30%属性卡
    │   │   └─ 后期（5分钟后）：30%武器，70%属性卡
    │   │   └─ ShopManager.generate_weapon()
    │   │       ├─ 随机weapon_id
    │   │       ├─ 随机品质（带权重，见weapons.csv的QualityWeight字段）
    │   │       │   └─ Excel中QualityWeight定义每个时间段的品质概率
    │   │       └─ 根据品质生成属性（白0个/蓝1个/紫3个）
    │   └─ 属性卡
    │       └─ ShopManager.generate_card()
    │           ├─ 随机属性类型（带权重钩子，见下文）
    │           └─ 随机数值
    └─ 显示商店UI
    ↓
玩家点击购买武器
    ↓
检查：gold >= 武器价格
    ↓

var gold := 0
var _gold_checksum := 0

func add_gold(amount: int):
    gold += amount
    _gold_checksum = _calculate_checksum(gold)
    gold_changed.emit(gold)

func spend_gold(amount: int) -> bool:
    if not _verify_gold():
        push_error("金币数据异常！")
        return false
    
    if gold >= amount:
        gold -= amount
        _gold_checksum = _calculate_checksum(gold)
        gold_changed.emit(gold)
        return true
    return false

func _verify_gold() -> bool:
    return _gold_checksum == _calculate_checksum(gold)

func _calculate_checksum(value: int) -> int:
    # 简单的校验算法（可以更复杂）
    return (value * 7919) ^ 0xDEADBEEF

## 🔗 模块关联关系详解

### 角色 ↔ 武器

**关联点1：属性继承**
```
Player.get_final_stat("crit_rate")
    ↓
Weapon读取此值用于暴击判定
```

**关联点2：装备加成**
```
Weapon的attributes属性
    ↓
Player.recalculate_equipment_bonus()
    ↓
累加到equipment_bonus
    ↓
影响get_final_stat()返回值
```

**关联点3：武器槽管理**
```
Player.weapon_slots[0-5]
    ↓
存储武器实例数据
    ↓
WeaponContainer下的子节点
```

### 武器 ↔ 商店

**关联点：武器生成**
```
ShopManager.generate_weapon()
    ↓
创建武器实例数据（包含品质+属性）
    ↓
玩家购买
    ↓
Player.add_weapon(weapon_data)
```

### 武器 ↔ 工坊

**关联点1：升阶**
```
ForgeManager.upgrade_weapon(weapon_data)
    ↓
修改weapon_data.quality
    ↓
增加weapon_data.attributes
    ↓
Player.recalculate_equipment_bonus()
```

**关联点2：重铸**
```
ForgeManager.reroll_attribute(weapon_data, index)
    ↓
重新生成weapon_data.attributes[index]
    ↓
Player.recalculate_equipment_bonus()
```

### 角色 ↔ 商店

**关联点：卡牌购买**
```
ShopManager.generate_card()
    ↓
返回{attribute, value}
    ↓
Player.add_shop_bonus(attribute, value)
    ↓
shop_bonus[attribute] += value
    ↓
影响get_final_stat()
```

### 角色 ↔ 怪物

**关联点1：战斗**
```
Weapon计算伤害
    ↓
Enemy.take_damage(damage)
    ↓
Enemy.die()
    ↓
GameManager.add_gold() / add_ore() / add_exp()
    ↓
Player升级或购买
```

**关联点2：受伤**
```
Enemy攻击
    ↓
Player.take_damage(damage)
    ↓
应用护甲减伤
    ↓
应用闪避判定
```

### 怪物 ↔ GameManager

**关联点：成长系统**
```
GameManager.current_minute
    ↓
Enemy._ready()
    ↓
GameData.get_monster_hp_at_minute(id, minute)
    ↓
根据时间计算属性
```

### 工坊 ↔ GameManager

**关联点：Boss限制**
```
GameManager.boss_killed信号
    ↓
ForgeManager.on_boss_killed()
    ↓
upgrades_this_boss = 0（重置升阶次数）
```

## 📝 数据表结构说明

### characters.csv（角色表）

**必需字段**：
```
id                  - 角色ID（唯一标识）
name_cn             - 中文名
name_en             - 英文名
initial_weapon      - 初始武器ID

# 基础属性（18个）
base_hp, base_hp_regen, base_lifesteal, base_armor, base_dodge, 
base_move_speed, base_all_dmg, base_cdr, base_crit_rate, base_crit_dmg, 
base_range, base_melee_dmg, base_ranged_dmg, base_element_dmg, base_summon_dmg

# 成长属性（15个，对应上面除了初始3个）
growth_hp, growth_hp_regen, growth_lifesteal, growth_armor, growth_dodge,
growth_move_speed, growth_all_dmg, growth_cdr, growth_crit_rate, growth_crit_dmg,
growth_range, growth_melee_dmg, growth_ranged_dmg, growth_element_dmg, growth_summon_dmg
```

**数据类型**：

- id, name_cn, name_en, initial_weapon：字符串
- 其他所有字段：浮点数

### weapons.csv（武器表）

**必需字段**：
```
id                  - 武器ID
name_cn             - 中文名
name_en             - 英文名
weapon_class        - 武器大类（melee/ranged/element/summon）
bonus_class         - 加成类别（M/R/E/S）
base_damage         - 基础伤害
damage_mult         - 伤害系数（继承系数，通常0.8-1.2）
base_cooldown       - 基础冷却（秒）
cooldown_mult       - 冷却系数
cdr_inherit         - 冷却效率继承百分比（0.0-1.0）
crit_mult           - 会心倍率（已废弃，用下面两个代替）
crit_rate_inherit   - 会心率继承百分比（0.0-1.0）
crit_dmg_inherit    - 会心伤害继承百分比（0.0-1.0）
attack_range        - 攻击范围（像素）
pierce_count        - 穿透次数（0=不穿透，仅远程武器）
pierce_dmg_mult     - 穿透伤害衰减（如0.7=穿透后伤害70%，仅远程武器）
projectile_speed    - 投射物速度（仅远程，像素/秒）
sprite_id           - 投射物精灵表ID（仅远程，对应VFX文件夹）
vfx_id              - 特效ID（对应VFX_Profiles）
icon_id             - 图标ID（对应wuqi/icon/256/文件名）
```

**武器类型特殊字段**：

近战武器（weapon_class=melee）：
- attack_range：攻击范围（CircleShape2D的radius）
- pierce_count：无效
- projectile_speed：无效

远程武器（weapon_class=ranged）：
- attack_range：射程
- pierce_count：穿透次数
- pierce_dmg_mult：穿透伤害衰减
- projectile_speed：必需
- sprite_id：必需

元素武器（weapon_class=element）：
- 根据是否有投射物，可以是近战范围或远程投射
- 如果是投射型：需要projectile_speed、sprite_id
- 如果是范围型：只需attack_range

召唤武器（weapon_class=summon）：
- 需要额外的召唤物配置（可能需要单独的summons.csv）


### monsters.csv（怪物表）

**必需字段**：
```
id                  - 怪物ID
name_cn             - 中文名
name_en             - 英文名
type                - 类型（small/medium/boss）
base_hp             - 初始生命
hp_growth_per_min   - 生命成长/分钟
base_damage         - 初始伤害
damage_growth_per_min - 伤害成长/分钟
base_speed          - 移动速度（像素/秒）
attack_range        - 攻击范围（像素）
attack_cooldown     - 攻击冷却（秒）
gold_drop           - 掉落金币
ore_drop_chance     - 掉落矿石概率（0.0-1.0）
```

**结构**：

key         - 文本键（如"health"）

en          - 英文（如"Health"）

## 📖 开发建议

### 给AI开发者的建议

1. **严格遵守数据结构**：不要自创字段名，必须和CSV表头一致
2. **先实现再优化**：先让功能跑通，再考虑性能
3. **每个函数都要注释**：说明参数、返回值、用途
4. **常量必须注释**：说明作用、调整范围、影响
5. **使用信号通信**：模块间用信号，不要直接调用
6. **测试每个功能**：完成一个任务就测试，不要堆积问题

### 给人类开发者的建议

1. **按Phase顺序开发**：不要跳跃，前面是后面的基础
2. **频繁测试**：每完成一个小功能就运行测试
3. **记录数值**：调整数值时记录原因，方便后期平衡
4. **保存版本**：每完成一个Phase就备份项目
5. **使用版本控制**：Git管理代码

### 召唤物属性计算

```gdscript
# summon_weapon.gd
func calculate_summon_stats() -> Dictionary:
    var summon_stats = {}
    
    # 基础伤害：武器基础伤害 + 玩家召唤伤害
    var base_dmg = weapon_data.get("base_damage", 10.0)
    var summon_bonus = player.get_final_stat("summon_dmg")
    summon_stats.damage = base_dmg + summon_bonus
    
    # 全伤害加成（总是继承）
    var all_dmg_mult = 1.0 + player.get_final_stat("all_dmg") / 100.0
    summon_stats.damage *= all_dmg_mult
    
    # 会心（检查是否解锁继承）
    if player.has_shop_bonus("summon_crit_inherit"):
        var inherit_rate = player.get_shop_bonus_value("summon_crit_inherit") / 100.0
        summon_stats.crit_rate = player.get_final_stat("crit_rate") * inherit_rate
        summon_stats.crit_dmg = player.get_final_stat("crit_dmg") * inherit_rate
    else:
        summon_stats.crit_rate = 0.0
        summon_stats.crit_dmg = 0.0
    
    # 冷却（检查是否解锁继承）
    if player.has_shop_bonus("summon_cdr_inherit"):
        var inherit_rate = player.get_shop_bonus_value("summon_cdr_inherit") / 100.0
        summon_stats.cdr = player.get_final_stat("cdr") * inherit_rate
    else:
        summon_stats.cdr = 0.0
    
    return summon_stats
```

# Godot 窗口任意缩放不模糊 - 技术实现方案

> **问题**：如何让游戏窗口可以任意拉伸，但保持像素清晰不模糊
> **参考**：土豆兄弟（Brotato）使用Godot 3.x制作，支持窗口任意缩放

---

## 核心原理

### 1. 高分辨率素材 + 最近邻采样
- **256×256的PNG母版** → 足够高的分辨率
- **禁用纹理过滤** → 使用Nearest Neighbor而非Linear
- **结果**：缩放时不会模糊，保持像素清晰

---

## Godot 4.x 完整配置方案

### 步骤1：项目设置 - 窗口配置

打开 **Project Settings** → **Display** → **Window**

#### Size 设置：
```
Viewport Width: 1920     # 内部渲染分辨率（宽）
Viewport Height: 1080    # 内部渲染分辨率（高）
Mode: 2 (Windowed)       # 窗口模式（可调整大小）
Resizable: ON            # 允许调整窗口大小
```

#### Stretch 设置：
```
Mode: canvas_items       # 缩放模式：画布项目
Aspect: expand           # 宽高比：扩展（自适应）
Scale: 1.0               # 缩放倍数：1.0
Scale Mode: fractional   # 支持非整数缩放
```

**关键点**：
- `canvas_items` 模式：UI元素会根据窗口大小缩放，保持相对位置
- `expand` 宽高比：窗口任意拉伸都能自适应，不会有黑边
- `fractional` 缩放：支持任意缩放比例（不限于2x、3x整数倍）

---

### 步骤2：纹理导入设置（全局）

打开 **Project Settings** → **Rendering** → **Textures**

```
Canvas Textures > Default Texture Filter: Nearest
Canvas Textures > Default Texture Repeat: Disabled
```

**或者在导入单个图片时**：
1. 选中图片文件
2. 切换到 **Import** 标签
3. 设置：
   - Filter: OFF（关闭过滤）
   - 或选择预设：`2D Pixel`
4. 点击 **Reimport**

**效果**：
- Filter OFF = Nearest Neighbor采样 = 像素风格清晰
- Filter ON = Linear采样 = 模糊（适合3D或照片）

---

### 步骤3：UI布局使用锚点

**错误做法**（固定像素）：
```gdscript
# ❌ 错误：写死坐标
label.position = Vector2(20, 20)
```

**正确做法**（使用锚点）：
```gdscript
# ✅ 正确：使用锚点 + Margin
# 在编辑器中设置：
Layout > Anchors Preset:
  - Top Left (左上角元素)
  - Top Right (右上角元素)
  - Bottom Left (左下角元素)
  - Bottom Right (右下角元素)
  - Center (居中元素)

# 然后调整Offset/Margin，而非直接改Position
```

**Control节点锚点说明**：
```
anchor_left: 0.0 (左边缘)
anchor_top: 0.0 (顶部边缘)
anchor_right: 1.0 (右边缘)
anchor_bottom: 1.0 (底部边缘)

offset_left/right/top/bottom: 相对锚点的偏移量
```

**示例：顶部居中标题**
```
Anchor Preset: Center Top
offset_left: -100  # 中心向左100px
offset_right: 100   # 中心向右100px
offset_top: 20      # 顶部向下20px
offset_bottom: 60   # 顶部向下60px（高度40px）
```

---

### 步骤4：精灵图scale设置

**关键理解**：
- 256×256是**母版尺寸**，不是最终显示尺寸
- 最终显示由**窗口缩放系统**决定，不需要手动scale

**在Sprite2D中**：
```gdscript
# 直接加载256×256的PNG
texture = load("res://assets/characters/hero.png")

# 不需要设置scale！
# scale会保持默认Vector2(1, 1)
# 最终显示大小由窗口缩放决定
```

**如果确实需要调整相对大小**：
```gdscript
# 某个角色原图256×256，想显示为128px效果
scale = Vector2(0.5, 0.5)

# 但窗口拉伸时，这个0.5会跟着缩放
# 所以256×0.5×窗口缩放 = 最终像素大小
```

---

## 为什么256×256母版不会模糊？

### 降采样原理
```
场景1：窗口小，256px缩小显示为128px
  - 256 → 128 = 降采样（丢弃多余像素）
  - 结果：清晰，无模糊

场景2：窗口大，256px放大显示为512px
  - 256 → 512 = 上采样（每个像素变成2×2）
  - 使用Nearest Neighbor：直接复制像素
  - 结果：像素风格，边缘清晰（不是模糊的渐变）

场景3：窗口拉伸，256px显示为300px（非整数倍）
  - 256 → 300 = 1.17x缩放
  - Nearest Neighbor会选择最近的像素
  - 可能有轻微的不均匀，但不会模糊
```

### 对比：低分辨率母版
```
如果用64×64母版：
  - 窗口放大到256px = 4x放大
  - 像素块变得很大，细节丢失
  - 虽然不模糊，但画质粗糙

256×256母版优势：
  - 支持缩小到32px（小怪）仍清晰
  - 支持放大到512px（Boss）细节足够
  - 高分辨率显示器（4K）也不会糊
```

## 常见问题

### Q1: 为什么有些像素游戏会要求整数缩放？
**A**: 那是为了完美的像素对齐。如果你的游戏需要：
- 每个游戏像素必须对应显示器的N×N像素（1×1、2×2、3×3）
- 避免"半像素"问题

则需要启用 **Integer Scaling**：
```
Scale Mode: integer   # 整数缩放（加黑边）
```

但土豆兄弟没有这么做，它允许fractional缩放以获得更灵活的窗口体验。

### Q2: UI图标256×256显示128×128，需要scale吗？
**A**: **不需要**！正确做法：

## 总结

**要实现窗口任意缩放不模糊**：

1. ✅ 使用256×256高分辨率母版
2. ✅ 纹理Filter设为OFF (Nearest Neighbor)
3. ✅ Stretch Mode = canvas_items
4. ✅ Stretch Aspect = expand
5. ✅ Scale Mode = fractional
6. ✅ UI使用锚点而非固定像素
7. ✅ 不要手动scale精灵图（交给缩放系统）

**核心思想**：
- 高分辨率素材 = 缩放时不损失细节
- Nearest Neighbor = 保持像素风格
- Fractional Scaling = 灵活适应任意窗口
- 锚点布局 = UI自适应
